# ShowTrack — Design Spec (2026-07-02)

Personal TV show + movie tracker in the style of TV Time, replacing the user's TV Time account.
Desktop app: **Tauri 2 + Rust core + SvelteKit (Svelte 5, TypeScript, adapter-static) + Vite + pnpm**.

- Location: `G:\Projects\showtrack`
- Identifier: `com.nokama.showtrack`
- Window title / app name: **ShowTrack**
- Single user, local only. No accounts, no sync, no social features.

## Goals (v1)

1. **Core tracking** — follow shows, mark episodes watched (per episode / season / show), track
   movies as watched or on a watchlist, favorites.
2. **Upcoming view** — see when the next episodes of followed shows air.
3. **Search & add** — find new shows/movies on TMDB and add them to the library.
4. **Import** — one-time (re-runnable) import of the TV Time export at
   `%USERPROFILE%\Downloads\tvtime-summary-2026-07-01.html`.

Explicitly **out of scope for v1**: stats page, ratings/notes/comments, notifications,
episode-level rewatch tracking, social/discover feeds, mobile.

## Source data: the TV Time export

HTML file generated by "TV Time Out by Refract". All data lives in two JS array literals:
`var SHOWS = [...]` and `var MOVIES = [...]` (one per line, plain JSON).

- **171 shows**, summary-level only: `title`, `tvdbId` (100% present), `imdbId` (mostly null),
  `status` (`up_to_date` 143 / `continuing` 20 / `not_started_yet` 5 / `stopped` 3),
  `isFavorite`, `watched`/`total` regular-episode counts, `totalSpecials`/`watchedSpecials`
  counts, `unwatchedRegularEps` (explicit `{season, episode}` list of NOT-watched regular
  episodes), `watchedNoDate` (0 for all shows), `ghostEntry`/`noEpisodeData`/`allMissingDates`
  flags and `flaggedEps` (all false/empty for every show in this export — the parser accepts
  these fields but the import ignores them). **No per-episode watch dates.** User decision: import watches with no date; real dates are
  recorded only for activity going forward.
- **594 movies** (553 watched): `title`, `tvdbId` (100%), `imdbId` (100%), `uuid`, `year`
  (2 nulls), `isWatched`, `isFavorite`, `watchedAt` (UTC datetime, 100% coverage on watched),
  `rewatchCount`.
- Export date `2026-07-01` is parsed from the document (title/footer).
- Known data loss (accepted): 6 watched specials across 3 shows are not identified individually
  by the export; they import as unwatched and are listed in the import report for manual re-tick.

## Architecture (chosen: local-first + cache)

Rust owns all data and network I/O; the frontend only renders and invokes Tauri commands.

- **SQLite** (via `rusqlite`) in the Tauri app-data dir is the source of truth for both personal
  state and cached TMDB metadata. App is fully usable offline from cache.
- **TMDB** is the sole metadata provider (free personal API key, entered by the user in
  Settings, stored in SQLite). Used for: ID mapping, show/episode/movie metadata, air dates,
  posters, search.
- **Images** (posters/stills/backdrops) are lazily downloaded to a disk cache
  (`<appdata>/images/…`) and served to the webview through a custom Tauri protocol; the
  frontend never fetches from TMDB directly.

### Data model (SQLite)

- `shows` — `tmdb_id` PK, `tvdb_id`, `imdb_id`, `name`, `year`, `poster_path`, `backdrop_path`,
  `overview`, `tmdb_status` (Returning Series / Ended / Canceled / …), `my_state`
  (`watching` | `stopped` | `plan_to_watch`), `is_favorite`, `added_at`, `last_refreshed_at`
- `episodes` — `tmdb_id` PK, `show_tmdb_id` FK, `season_number`, `episode_number`, `name`,
  `air_date`, `runtime`, `still_path`, `overview`
- `episode_watches` — `episode_tmdb_id` FK, `watched_at` **nullable** (NULL = imported,
  timestamped = marked in-app), `source` (`import` | `app`)
- `movies` — `tmdb_id` PK, `tvdb_id`, `imdb_id`, `tvtime_uuid`, `title`, `year`, `release_date`,
  `runtime`, `poster_path`, `backdrop_path`, `overview`, `my_state` (`watched` | `watchlist`),
  `watched_at`, `rewatch_count`, `is_favorite`, `added_at`
- `settings` — key/value (TMDB API key, last import info, prefs)
- Schema is versioned (`PRAGMA user_version`) for future migrations.

Status mapping on import: `up_to_date`/`continuing` → `watching`; `stopped` → `stopped`;
`not_started_yet` → `plan_to_watch`. "Caught up" is always computed from watch data, never stored.

### TMDB client (Rust)

`reqwest`-based, behind a trait so tests can mock it. Endpoints:

- `/find/{external_id}` with `external_source=tvdb_id` (shows) / `imdb_id` (movies)
- `/tv/{id}` (+ `append_to_response=season/N,…`, ≤20 seasons per call) and
  `/tv/{id}/season/{n}` for episode lists
- `/movie/{id}`
- `/search/multi`
- `image.tmdb.org` for artwork

Throttled (small concurrency, ~40 req/s ceiling). All calls cancellable.

### Refresh strategy

On app launch and via a manual Refresh button: re-fetch show + episode data for shows with
`my_state = watching` whose `tmdb_status` is not Ended/Canceled. Ended shows and movies are never
auto-refreshed. Offline → refresh silently skipped, dismissible banner shown, app runs from cache.

## Import flow

First-run wizard (after TMDB key entry), re-runnable from Settings. Runs as a background job
emitting progress events (same pattern as qobuz-dl); upserts only, never deletes.

1. User picks the export HTML. Rust extracts the `var SHOWS`/`var MOVIES` lines, strips the JS
   prefix/suffix, parses with `serde_json`. Export date parsed from the document.
2. **Shows**: `/find` by TVDB id → fetch full episode list → insert show + episodes → mark
   watched every **regular** episode (season > 0) with `air_date <= export_date`, **except**
   entries in `unwatchedRegularEps`. Watches get `watched_at = NULL`, `source = import`.
   Specials (season 0) import as unwatched.
3. **Movies**: `/find` by IMDb id → `/movie/{id}` → insert with `my_state` from `isWatched`
   (watched vs watchlist), `watched_at` from export, `rewatch_count`, `is_favorite`.
4. **Import report** at the end:
   - failures (find-miss, network, etc.) with per-item retry;
   - **anomalies**: shows whose computed watched count ≠ export's `watched` count (typically
     TVDB↔TMDB episode-numbering drift, worst for anime) — listed for manual fix-up;
   - the 3 shows with watched specials, for manual re-ticking.

## UI

Dark, poster-forward. Slim sidebar: **Shows · Upcoming · Movies · Search · Settings**.
All mutations optimistic (instant UI, Rust persists behind the scenes).

- **Shows** (default; TV Time's "Watch Next"): cards for `watching` shows — poster, progress
  (e.g. 47/62) and the next unwatched episode with a one-tap ✓ that advances to the following
  episode. Caught-up shows collapse into an "Up to date" section. Filter chips:
  watching / plan to watch / stopped / all; text filter.
- **Upcoming**: future-dated episodes of followed shows, chronological, grouped by day, with
  poster, SxxEyy, episode name, countdown ("in 3 days").
- **Movies**: poster grid, Watched / Watchlist tabs, sort by watch date / title / year.
  Mark-watched stamps now; rewatch button increments `rewatch_count`; favorite toggle.
- **Show detail**: backdrop header (poster, overview, TMDB status), `my_state` selector,
  favorite; collapsible seasons; per-episode rows (SxxEyy, name, air date, check);
  mark-season-watched; mark-all-watched.
- **Movie detail**: modal/panel — poster, overview, state, watched date, rewatches, favorite.
- **Search**: TMDB multi-search (TV + movies), poster results; adding a show asks
  watching vs plan-to-watch; adding a movie asks watchlist vs watched-now.
- **Settings**: TMDB API key, re-run import, manual full refresh, cache location/size info.

## Error handling

- No TMDB key → onboarding screen (key entry + validation + link to TMDB signup) before
  anything else; import wizard offered right after.
- Import/API failures are per-item, never abort the whole job; failures are retryable from the
  report.
- Offline: banner + cached data; no broken screens.
- DB: versioned migrations; file/DB work in `spawn_blocking`; short-lived locks only (no lock
  held across I/O — the qobuz-dl poisoned-mutex lesson).

## Testing

- **Rust unit tests**: export parser against a trimmed anonymized fixture; watched-marking rules
  (export-date cutoff, `unwatchedRegularEps` exclusion, specials exclusion); status mapping; DB
  layer round-trips; import anomaly computation.
- **TMDB client**: trait-mocked tests for mapping/refresh logic; one `#[ignore]`d live smoke
  test (find + fetch a known show) run manually with the real key.
- **Frontend**: `svelte-check` and `pnpm build` clean; manual smoke via `pnpm tauri dev`.
- Build follows qobuz-dl practice: runnable exe via `pnpm tauri build --no-bundle` (never bare
  `cargo build --release` for the shipping exe).

## Known limitations (accepted for v1)

- Imported episode watches carry no dates → any future stats feature will have a dateless
  backlog for pre-import history.
- TVDB↔TMDB numbering drift can mis-mark a few episodes on some shows (surfaced via the
  anomaly report rather than silently ignored).
- Specials watch-state from TV Time is lost (6 specials, listed for manual re-tick).
- Movies with no IMDb match on TMDB fall back to failure list + manual search-and-add.
- Import retry is whole-run re-import (safe: metadata upserts + INSERT OR IGNORE watches +
  user-state applied only to newly inserted rows) rather than the per-item retry buttons
  originally envisioned; TMDB calls during import are not cancellable (one-shot job).
